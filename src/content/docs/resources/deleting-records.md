Deleting a record is a **write-side operation**. The current Resource system has Page GET routes and Policy-backed record resolution but does **not** automatically expose DELETE endpoints or destructive actions.

:::caution[Not yet a built-in Resource feature]
Do not call a DELETE Resource URL unless your Laravel application registered and tested that endpoint. Filament's `DeleteAction` and bulk-delete actions are **not Lavertia components**.
:::

## A safe host implementation

A delete endpoint should be located behind the same `auth` and tenant middleware as the Resource and should require a CSRF-protected Inertia DELETE request.

~~~php
public function destroy(Request $request, string $record): RedirectResponse
{
    $ticket = TicketResource::query()->whereKey($record)->firstOrFail();

    Gate::authorize('delete', $ticket);

    DB::transaction(function () use ($ticket): void {
        $ticket->delete();
    });

    return redirect()->to(TicketResource::getUrl('list', panelId: 'admin'));
}
~~~

This is **Laravel host code**, not a method generated by Lavertia. When applicable, use Eloquent `SoftDeletes` and check whether cascading foreign keys, financial ledgers, related attachments or audit records require a different lifecycle.

## Design the confirmation UX

Use a reusable Lavertia Action component that invokes your registered DELETE route, confirms the target name, offers keyboard dismissal, and exposes processing/success/error states. The current Action protocol alone is not proof that a destructive confirmation/dialog/undo flow is implemented.

Never rely on hiding a Delete button to enforce authorization. The final controller action must run `Gate::authorize('delete', $ticket)` after scoping the record.

## Bulk deletion (planned)

Bulk selection requires a bounded list of record IDs, an authorized scoped query, per-model or bulk Policy decisions, transaction size limits, audit logging and partial failure UX. A dedicated bulk-action protocol is planned; blindly mass-deleting IDs supplied by the browser is unsafe.

See [Filament 5 Deleting records](https://filamentphp.com/docs/5.x/resources/deleting-records) for related design ideas.
